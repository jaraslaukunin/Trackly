# Политика безопасности

## Как сообщить об уязвимости

Проект учебный, но обрабатывает медицинские данные, поэтому к вопросам безопасности
мы относимся серьёзно.

- Не создавайте публичный issue с описанием уязвимости.
- Напишите владельцу репозитория через GitHub (профиль → **Contact**) и укажите:
  шаги воспроизведения, ожидаемое и фактическое поведение, потенциальный ущерб.
- Мы постараемся ответить в течение 7 дней.

## Секреты

В репозитории **не должно быть** реальных ключей. Значения читаются из окружения:

| Переменная | Где используется |
| --- | --- |
| `TRACKLY_SUPABASE_URL` | клиент (Qt) |
| `TRACKLY_SUPABASE_ANON_KEY` | клиент (Qt) |
| `TRACKLY_AI_PROXY_KEY` | клиент (Qt), AI-аналитика |
| `SUPABASE_SERVICE_ROLE_KEY` | только Edge Functions |
| `RESEND_API_KEY` | только Edge Functions |

Если ключ всё же попал в коммит — недостаточно удалить его новым коммитом:

1. **Сразу отзовите ключ** в панели провайдера (Supabase / proxyAPI / Resend).
2. Очистите историю (`git filter-repo` или `git filter-branch`) либо пересоздайте репозиторий.
3. Проверьте, что ключ не остался в открытых форках и в кэше поисковых систем.

## Работа с данными

- Доступ к строкам в Postgres ограничен RLS-политиками; клиент использует только anon-ключ.
- Сессия пользователя хранится локально в `QSettings` (access/refresh token).
- Файлы обследований лежат в бакете Storage `medical_files`.

## Область применения

Приложение не является медицинским изделием, не ставит диагнозы и не даёт
медицинских рекомендаций. AI-сводка носит исключительно статистический характер.
